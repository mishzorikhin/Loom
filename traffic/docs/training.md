# Обучение: среда и управление

Как подключить обучение к симулятору. Описано то, что есть в коде (`tsim/env.py`, `tsim/rollout.py`, `tsim/signals.py`, `tsim/sim.py`); чего нет, помечено как замысел. Самой нейросети и цикла обучения в репозитории нет: есть среда, эталонные политики и прогон для сравнения.

## Быстрый старт

```python
import random
from tsim.env import TrafficEnv

env = TrafficEnv("grid2", seed=1, decision=5, episode=1200)
obs = env.reset()                          # {id перекрёстка: np.ndarray(env.obs_size)}
done = False
while not done:
    actions = {jid: int(random.choice(env.action_mask(jid).nonzero()[0])) for jid in env.agents}
    obs, rewards, done, info = env.step(actions)   # rewards: {id: float <= 0}
print(info["metrics"])
```

Сравнение политик из консоли (случайная по маске, «не переключать», max-pressure):

```
python3 -m tsim.rollout --world grid2 --policy random,hold,max_pressure --episodes 3 --minutes 20
python3 -m tsim.rollout --world irregular --policy mypkg.mymodule:policy
```

Своя политика — функция `policy(env, obs, rng) -> {id: действие}` (образцы в `tsim/rollout.py`). Эталон для сравнения без среды: `python3 -m tsim.run` (контроллеры `fixed`, `max_pressure` внутри симулятора, см. README).

## Агенты и шаг

- Агент — перекрёсток со светофором (`kind == "signal"`): `env.agents`, список id. Переходы посреди квартала агентами не являются: они работают по вызову пешехода, код управляет ими сам.
- Один шаг среды — `decision` секунд симуляции (по умолчанию 5; шаг ядра `DT = 0,1 с`, то есть 50 шагов ядра). Агенты ходят одновременно: `step(actions)` принимает действия всех (или части) агентов; агент без действия оставляет всё как есть.
- Конец эпизода — `done = True`, когда время симуляции дошло до `episode` секунд (по умолчанию 3600). Усечения по аварии нет: ДТП блокирует полосу на 150 с и эпизод идёт дальше.
- Детерминизм: одинаковые мир, зерно (`reset(seed=...)`), параметры и последовательность действий дают одинаковый эпизод (`tests/test_sim.py`).

Параметры `TrafficEnv(world, seed, decision, episode, demand, peds, timing_scale, start_hour, weights, obs_spec)`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `world` | `"cross"` | имя из `tsim/worlds.py` (`cross`, `corridor`, `grid`, `grid2`, `district`, `irregular`), путь к JSON или словарь описания |
| `seed` | 1 | зерно случайности; в `reset(seed=)` можно сменить |
| `decision` | 5 с | как часто агент выбирает действие |
| `episode` | 3600 с | длина эпизода |
| `demand`, `peds` | 1,0 | множитель потока машин и пешеходов (0…3) |
| `timing_scale` | 1,0 | запас переходных стадий: 1 — безопасные длительности, ниже 1 появляются ДТП по вине светофора (вариант B), 0 — без жёлтого и красного |
| `start_hour` | 7,5 | час начала суток: спрос зависит от времени (пики 8:00 и 17:30, ночью 8%) |
| `weights` | см. «Награда» | словарь, переопределяет веса награды |
| `obs_spec` | `None` | общая раскладка `ObservationSpec`; без неё размеры считаются по текущему миру |

Запрет въезда на занятый перекрёсток (`block_box`) в среде всегда включён.

## Наблюдение

Для каждого агента вектор `np.float32` длиной `env.obs_size`; имена элементов — `env.obs_layout()`. Раскладка:

| Блок | Размер | Что |
|---|---|---|
| полосы подхода | `max_lanes × 4` | по подходящей полосе (порядок `junction.approaches`): `queue/20`, `count/30`, `speed/15`, `wait/120` |
| фаза | `max_phases` | one-hot текущей фазы |
| стадия | 3 | one-hot: `green`, `change` (жёлтый/мигающий), `all_red` |
| время зелёного | 1 | `min(green_t, 180)/60` |
| ждущие пешеходы | `max_ped` | по пешеходным группам: `waiting/10` |

Признаки полосы считаются на отрезке до 100 м перед стоп-линией: `count` — машин, `speed` — их средняя скорость (м/с), `queue` — машин медленнее 1,5 м/с в пределах 70 м, `wait` — наибольшее ожидание в очереди (с, не больше 300). Значения не обрезаются до единицы: `queue` выше 20 даёт больше 1.

Без `obs_spec` размеры `max_lanes`, `max_phases`, `max_ped` — максимумы по текущему миру; короткие векторы добиваются нулями. Размер зависит от мира: `cross` и `grid` — 43, `district` — 44, `irregular` — 35. Богаче вектора данные в `sim.junction_obs(jid)`: `phase_pressure` по фазам (признак для max-pressure), точные очереди, ждущие пешеходы по группам.

Для одной модели на разных мирах передайте общую `ObservationSpec`:

```python
from dataclasses import asdict
from tsim.env import ObservationSpec, TrafficEnv

spec = ObservationSpec.from_worlds(["cross", "grid2", "district", "irregular"])
env = TrafficEnv("grid2", obs_spec=spec)
other = TrafficEnv("irregular", obs_spec=spec)
assert env.obs_layout() == other.obs_layout()
assert env.max_actions == other.max_actions
saved_spec = asdict(spec)  # сохранить рядом с весами модели, например в JSON
restored = ObservationSpec(**saved_spec)
```

`from_worlds` принимает список имён, путей к JSON или описаний миров. Размеры можно задать явно: `ObservationSpec(max_lanes=16, max_phases=8, max_ped=8)`. Для нового мира, не помещающегося в раскладку, конструктор выдаёт `ValueError`; полосы и фазы не усекаются. Для сохранённой модели используйте сохранённую раскладку: её изменение меняет позиции признаков.

Единый размер не делает номера полос и фаз одинаковыми по смыслу. Поэтому графовый снимок также содержит геометрию полос и связи фаз с разрешёнными движениями и переходами.

## Вход графового трансформера

`env.graph()` доступен до `reset()` и возвращает статическую топологию: `nodes` (id в порядке `env.agents`), `edges` (отсортированные пары индексов источник → получатель), `edge_features` и `edge_feature_names`. Ребро объединяет сквозные полосы между двумя светофорными узлами; обратное направление — отдельное ребро, если оно есть. Коннекторы внутри перекрёстка и дороги к краям сети в рёбра не входят; карманы не увеличивают число сквозных полос. Переход посреди дороги не разрывает связь между светофорами.

Признаки ребра идут в порядке `edges` и нормализованы:

| Признак | Смысл |
|---|---|
| `distance/100` | расстояние между центрами перекрёстков, м / 100 |
| `length/100` | средняя длина сквозной полосы между стоп-линиями, м / 100 |
| `travel_time/10` | среднее время проезда полосы с разрешённой скоростью, с / 10; без задержек и переходных стадий |
| `lanes/4` | число сквозных полос данного направления / 4 |
| `direction.x`, `direction.y` | единичный вектор от источника к получателю в координатах мира |

Если несколько дорог соединяют одну пару узлов, их сквозные полосы объединяются. Признаки рёбер статические: текущую загрузку модель получает из признаков узлов.

После `reset()` метод `env.graph_observation()` собирает свежий снимок всей сети:

| Поле | Размер и тип | Смысл |
|---|---|---|
| `nodes` | список `N` id | порядок строк всех массивов узлов |
| `x` | `(N, obs_size)`, float32 | те же наблюдения, что в `reset()` / `step()` |
| `feature_mask` | `(N, obs_size)`, bool | `True` для реальных признаков; `False` для дополнения нулями |
| `lane_attr` | `(N, max_lanes, 6)`, float32 | направление движения к стоп-линии (`x`, `y`), длина / 100 м, скорость / 15 м/с, ширина / 4 м, длина кармана / 100 м |
| `lane_feature_names` | список 6 имён | раскладка `lane_attr` |
| `lane_mask` | `(N, max_lanes)`, bool | реальные полосы подхода |
| `phase_mask` | `(N, max_phases)`, bool | реальные фазы независимо от возможности переключения сейчас |
| `ped_mask` | `(N, max_ped)`, bool | реальные пешеходные группы |
| `phase_lane_mask` | `(N, max_phases, max_lanes)`, bool | фаза обслуживает хотя бы одно движение с полосы |
| `phase_movement_mask` | `(N, max_phases, max_lanes, 4)`, bool | разрешённые движения с полосы по фазам |
| `movement_names` | список 4 имён | порядок: `right`, `straight`, `left`, `uturn` |
| `phase_ped_mask` | `(N, max_phases, max_ped)`, bool | пешеходные группы, зелёные в каждой фазе |
| `edge_index` | `(2, E)`, int64 | первая строка — источники, вторая — получатели |
| `edge_attr` | `(E, 6)`, float32 | нормализованные признаки рёбер |
| `edge_feature_names` | список 6 имён | раскладка `edge_attr` |
| `attention_mask` | `(N, N)`, bool | `True` разрешает внимание к себе и соседу по дороге в любом направлении |
| `action_mask` | `(N, max_actions)`, bool | доступные действия сейчас |

Направления рёбер сохраняются, а внимание разрешено и к узлам выше, и к узлам ниже по потоку: это позволяет учитывать приближающиеся машины и перегруженный выезд. Маска разрешения внимания относится к одному слою; два слоя передают информацию через двух соседей. Если библиотека принимает маску запретов, используйте инверсию `~attention_mask`.

Для единственного перекрёстка `E = 0`: `edge_index` имеет размер `(2, 0)`, `edge_attr` — `(0, 6)`, внимание разрешено к самому себе. До `reset()` вызов `graph_observation()` выдаёт `RuntimeError`. Каждый вызов возвращает новые массивы, которые можно сохранять в буфер опыта.

```python
env = TrafficEnv("grid2")
env.reset()
data = env.graph_observation()
# Вход будущей модели: data["x"], data["edge_index"], data["edge_attr"], маски.
# Для перевода на GPU: torch.as_tensor(data["x"], device="cuda").
actions = {jid: int(data["action_mask"][i].nonzero()[0][0])
           for i, jid in enumerate(data["nodes"])}
obs, rewards, done, info = env.step(actions)
data = env.graph_observation()  # обновить и признаки, и маску действий
```

Это подготовка данных для модели, самой модели и обучения пока нет. Общая `obs_spec` фиксирует ширину `x`, ёмкости полос, фаз и пешеходных групп, число узлов и рёбер может меняться. Модели следует учитывать геометрию и связи движений с фазами, исключать дополнение нулями из внимания и применять `action_mask` перед выбором действия. Совместимый формат позволяет подключить одни веса к разным мирам; качество переноса проверяется экспериментами.

## Действие

За шаг среды на каждого агента — номер фазы или словарь:

```python
actions = {"j1": 2, "j2": {"phase": 1, "yellow": 3.0, "all_red": 2.0, "ped_flash": 6.0}}
```

- Номер совпал с текущей фазой — **держать** зелёный.
- Другой номер — запрос перехода. Он исполняется, только если стадия `green` и зелёный длится не меньше минимума `bounds.green[0]`. Иначе запрос **молча игнорируется**: агент остаётся на текущей фазе. Игнор виден в `info["ignored"][jid]`.
- Переход идёт по стадиям: жёлтый (машинам) и мигающий (пешеходам) → весь красный → новый зелёный. Порядок держит код.
- Длительности `yellow`, `all_red`, `ped_flash` в словаре обрезаются по `bounds` перекрёстка; если не заданы — безопасные значения, умноженные на `timing_scale`. Опасно малые значения разрешены (в этом и смысл варианта B): они приводят к ДТП по вине светофора и штрафуются наградой.
- Число фаз у перекрёстка своё: `env.n_actions(jid)`; в мире `irregular` оно 3 или 6. Номер за пределами числа фаз игнорируется.
- Маска: `env.action_mask(jid)` → `np.ndarray(bool, env.max_actions)`; `True` у текущей фазы всегда и у остальных, пока переход разрешён (зелёная стадия после минимума). Для общей сети с фиксированным выходом из `max_actions` нужна именно маска.

Фазы переходов посреди квартала в агентах не участвуют.

## Награда

На каждого агента за шаг среды, не больше нуля:

```
r = −( w_queue · средняя_очередь + w_near · сближения + w_crash · ДТП + w_ped_wait · средние_ждущие_пешеходы )
```

- `средняя_очередь` — сумма `queue` по подходам перекрёстка, усреднённая по секундам шага (замеры раз в секунду симуляции);
- `средние_ждущие_пешеходы` — число пешеходов в состоянии «ждёт» у переходов перекрёстка, усреднённое так же;
- `сближения` — число событий `near_miss` (TTC, PET, проезд рядом с пешеходом) за шаг у этого перекрёстка;
- `ДТП` — число событий `crash` за шаг у этого перекрёстка.

Событие относится к перекрёстку, указанному в событии, иначе к ближайшему в радиусе 60 м; события дальше в награды не попадают.

Веса по умолчанию: `queue 0,1`, `near 2,0`, `crash 50,0`, `ped_wait 0,05`; меняются через `TrafficEnv(weights={"crash": 100})`. Проезды на красный, переходы на красный и резкие торможения в награду не входят, но считаются в метриках.

## Метрики

`info["metrics"]` — накопленные за эпизод итоги всей сети (сбрасываются при `reset`):

`cars`, `peds` (сейчас в сети), `spawned`, `done` (доехавшие), `travel`, `delay`, `stops` (средние на доехавшую машину), `waiting`, `crashes`, `causes` (причины ДТП), `near` (по видам), `red_runs`, `jaywalks`, `stuck`, `hard_brakes`, `peds_done`, `ped_wait`, `blocked_spawn`.

Остальное в `info`: `t` и `clock` (время симуляции), `near` и `crash` (счётчики шага по агентам), `ignored` (какие запросы переходов не исполнены), `queue` и `ped_waiting` (средние за шаг числа машин в очередях и ожидающих пешеходов по агентам; те же замеры, что в награде).

Для сравнения политик берут задержку (`delay`), число доехавших (`done`), `crashes`, сумму `near` и `ped_wait` на нескольких зёрнах (`python3 -m tsim.rollout` и `python3 -m tsim.run`). Один эпизод — шумный: ДТП редки, зёрен нужно несколько.

## Проверка модели и сравнение с автоматическими светофорами

В `rollout` политики `fixed` и `automatic_max_pressure` используют те же контроллеры, что на странице, на каждом шаге ядра. Прежняя `max_pressure` — упрощённый эталон, принимающий решения только раз в `decision`; для сравнения с автоматикой страницы выбирайте `automatic_max_pressure`.

```bash
python3 -m tsim.rollout --world grid2 --layout-worlds cross,grid2,district,irregular --policy fixed,automatic_max_pressure --episodes 20 --seed 101 --minutes 30 --json > comparison.json
# После появления модели: --policy fixed,automatic_max_pressure,mypkg.mymodule:policy
```

Политики в одном запуске получают одинаковые настройки мира, спроса, пешеходов, переходных стадий, времени суток и список зёрен. `--seed` задаёт начало диапазона (в примере 101…120), `--peds` — пешеходный спрос, `--timing` — запас стадий. Генератор случайности политики заново создаётся для каждого эпизода; функция модели должна сбрасывать собственную память при смене `env.sim` и выключать случайность, если нужна детерминированная оценка.

Совпадающее зерно гарантирует повтор одинакового эпизода при одинаковых действиях. Оно **не гарантирует одинаковые будущие приезды при разных контроллерах**: спрос и поведение пока используют общий генератор случайности, а число его вызовов зависит от состояния. Точное сравнение на одной заранее заданной последовательности поездок потребует разделить случайные потоки или добавить воспроизведение спроса; этого пока нет.

JSON-отчёт содержит настройки, хеш мира, раскладку, результаты каждого зерна и средние со стандартным отклонением. `queue_mean` — среднее число машин в очередях по всей сети за эпизод, `ped_waiting_mean` — аналогично для ожидающих пешеходов. Учитывайте остаток машин (`cars`), `blocked_spawn` и `stuck`: задержка только доехавших (`delay`) может выглядеть хорошей, даже когда остальные застряли. Награда (`return`) помогает обучению, но не заменяет эти метрики.

Для итоговой оценки используйте зёрна, не участвовавшие в обучении, несколько уровней спроса, утро/вечер и отдельные миры. Результат лучше, если уменьшаются очереди и задержки, больше машин доезжает, а ДТП, сближения и ожидание пешеходов не растут.

Два мира рядом полезны для визуального разбора, их не обязательно запускать одновременно для измерения качества. Пока сравнение доступно без картинки; подключения модели к странице и синхронного показа двух прогонов ещё нет.

## Скорость

Среда считает быстрее реального времени (измерено на этой машине, шаг 5 с, случайная политика): `cross` ≈ ×390, `grid2` ≈ ×120, `district` ≈ ×110, `grid` ≈ ×80. Python-объекты в ядре (см. «Известные ограничения» в `design.md`): для больших сетей ядро придётся ускорять, интерфейс `Sim` при этом не меняется.

## Как строить обучение

1. Эталоны: `fixed` и `max_pressure` (`tsim.run`, `tsim.rollout`). Нейросеть должна их обойти по задержке без роста ДТП и сближений.
2. Сначала один перекрёсток (`cross`), затем `grid2` и `grid`. Мир `irregular` (звезда и Т-перекрёсток) — проверка раскладки на перекрёстках с разным числом фаз.
3. Для обобщения менять зёрна, `demand`, `start_hour`. Начало в 7:30 — утренний пик; чистый вечер и ночь требуют `start_hour`.
4. Если нужен вариант B (политика сама выбирает длительности стадий), оставьте `timing_scale = 1`: безопасные значения по умолчанию, а опасный выбор агент делает явно через `yellow`/`all_red`/`ped_flash`. Ползунок «запас» на странице нужен для ручных экспериментов, в среде это `timing_scale`.
5. Одна сеть на несколько миров: общая `ObservationSpec`, `graph_observation()`, геометрия полос и связи фаз с движениями. Сохраните раскладку вместе с весами.

## Чего нет (замысел)

- Показа обученной политики на странице: контроллер «внешний агент» на странице сам ничего не решает, команды `phase` по сокету переводят перекрёсток в ручной режим. Чтобы увидеть политику, пока можно гнать эпизод через `tsim.rollout` и смотреть метрики.
- Сохранения и повтора эпизодов (хеш сети + спрос + зерно + действия), журнала в Parquet и файлов экспериментов с правками мира.
- Формата спроса отдельным файлом: спрос задаётся множителями `demand` и `peds` и суточной кривой в коде.
