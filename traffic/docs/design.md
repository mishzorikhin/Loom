# Проект транспортной симуляции

Симулятор городской транспортной сети для обучения нейросети управлять светофорами: улицы, перекрёстки, машины, светофоры, пешеходы, ДТП. Нужен визуальный контроль и данные для обучения.

Статус: проект. Кода ещё нет. Всё ниже — принятые решения и замысел, а не описание работающей программы.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Чем управляет нейросеть | Только светофорами: когда переключать фазу и на какую, длительности стадий в пределах `bounds` |
| Логика машин | Минимальная: ехать на зелёный, следовать разметке и стрелкам, держать дистанцию, уступать пешеходу при повороте |
| Пешеходы | Есть с первой версии |
| Аварии по вине светофора | Вариант B: контроллер выбирает длительности жёлтого, всего красного и мигающего в широких пределах, вплоть до нуля; опасный выбор приводит к ДТП |
| Полосы | Разные: стрелки на полосе (`прямо`, `прямо и направо`, `только налево` и т. д.), карманы |
| Описание мира | JSON по схеме `schema/world.schema.json`, формат — `world-format.md` |
| Отрисовка | Строится из скомпилированной сети, не из готовых картинок; вид сверху, WebGL |
| Движок | Свой, без LLM. SUMO — только эталон для сверки пропускной способности и задержек |
| Связь с Loom | Нет. Отдельный проект в каталоге `traffic/` того же репозитория |

## Слои

```
описание мира (JSON)  ── компилятор ──►  скомпилированная сеть
                                            │            │
                       спрос (JSON) ──►  ядро симуляции  отрисовка
                                            │    ▲
                         журнал, эпизоды ◄──┤    │ действия
                                            ▼    │
                                  среда для обучения (PettingZoo / Gymnasium)
                                            ▲
                         контроллеры: фиксированный, max-pressure, нейросеть
```

- **Ядро без экрана и детерминировано**: фиксированный шаг (0.1–0.5 с), одно зерно случайности, скорость не привязана к реальному времени. Обучение гоняет эпизоды без картинки, любой эпизод можно посмотреть потом.
- **Отрисовка ничего не считает**: получает сеть один раз и кадры по сокету.

## Описание мира и компилятор

Два уровня:

1. **Описание** — смысл: узлы, дороги, полосы со стрелками, переходы, сигнальные группы и фазы. Пишет человек или генератор (решётка, магистраль, импорт OSM).
2. **Скомпилированная сеть** — выводится из описания: осевые линии полос, коннекторы через перекрёстки, точки конфликтов, граф тротуаров, примитивы разметки.

Симуляция и картинка берут сеть из одного источника. Стрелка «только налево» на экране стоит ровно там, где физика запрещает ехать прямо. Правила формата и компилятора — `world-format.md`.

Самая сложная часть компилятора — геометрия перекрёстка: обрезка дорог, скругление углов, кривые коннекторов. Начинать с прямых дорог под любыми углами.

## Граф полос и разметка

Разметка задаётся рёбрами графа полос, а не отдельной логикой:

- **продолжение** — полоса → следующая полоса;
- **поворот** — полоса → коннектор, только по стрелкам полосы;
- **перестроение** — полоса → соседняя полоса, только где линия прерывистая.

Маршрут машины — путь в этом графе от точки появления до выезда, строится при появлении. Запрещённых манёвров в графе просто нет.

## Машины

Состояние — плотные массивы numpy (по полю на массив), а не объекты:

```
lane[N], s[N], v[N], a[N], length[N], width[N]   положение вдоль полосы или коннектора
route[N][k], route_ptr[N]                        путь в графе полос
reaction[N], v_desired[N], headway[N], b_comf[N] параметры водителя
red_run_p[N], distraction[N]                     параметры ошибок
state[N]: driving | stopped | yielding | crashed
```

Машина движется по одной координате `s`. Переход в `(x, y, угол)` — только для отрисовки, по осевой линии из сети.

Правила:

1. **Дистанция** — модель IDM. Лидер — ближайшее препятствие по маршруту: машина впереди на этой полосе, иначе первая машина на следующем коннекторе или полосе, иначе стоп-линия, если перед ней нужно стоять.
2. **Сигнал**:
   - красный — стоп-линия становится неподвижным лидером;
   - жёлтый — остановка, если хватает комфортного торможения, иначе проезд (зона дилеммы);
   - зелёный — стоп-линии нет.
3. **Разметка** — только рёбра графа полос. Перестроение в первой версии простое: при достаточном интервале в соседней полосе на прерывистой линии.
4. **Уступить пешеходу** — в точке конфликта с правилом `yield` машина останавливается перед переходом, если пешеход на нём или вступит раньше, чем машина проедет.
5. **Не въезжать в занятый перекрёсток** — параметр. Без него возникают заторы, запирающие перекрёсток, и сеть учится их избегать.

## Пешеходы

Двигаются по графу тротуаров по той же схеме: `edge[M], s[M], offset[M], v[M]`.

- Идут на свой зелёный, на мигающем не начинают переход.
- Скорость разная: медленные не успевают закончить переход.
- Нетерпение растёт со временем ожидания, вместе с ним вероятность перейти на красный.

## Светофоры

Состояние перекрёстка: `phase`, `stage` (`green`, `yellow`/`ped_flash`, `all_red`), `elapsed`.

- Порядок стадий держит код.
- Контроллер раз в шаг решения (около 5 с) выбирает: оставить фазу или перейти на фазу k, и с какими длительностями переходных стадий в пределах `bounds`.
- Безопасность фаз проверяет компилятор: в одной фазе нет конфликтующих групп машин; конфликт машины с пешеходом — только с правилом `yield`.

## ДТП и опасные сближения

ДТП вытекают из поведения, а не выпадают случайно.

**По вине светофора** (главное для обучения):
- машина въехала на позднем жёлтом, а поперечное направление уже получило зелёный — короткий жёлтый или весь красный;
- пешеход не успел закончить переход, а машинам уже зелёный — короткий мигающий;
- частые переключения увеличивают число попаданий в зону дилеммы.

**По вине водителя и пешехода** (фон, параметры):
- задержка реакции → удар сзади;
- редкий проезд на ранний красный;
- переход на красный от нетерпения.

**Обнаружение** обходится без двумерной геометрии:
- на полосе — зазор до лидера меньше нуля (удар сзади);
- на перекрёстке — две машины (или машина и пешеход) одновременно накрывают свои точки конфликта: интервал `[s − length, s]` содержит `s_a` и `s_b`.

**Последствия**: участники встают, полоса или коннектор заблокированы на заданное время, потом участники убираются.

**Опасные сближения** считаются на каждом шаге, потому что ДТП редки и дают мало сигнала для обучения:
- TTC — время до столкновения на полосе;
- PET — интервал между выездом одного участника из точки конфликта и въездом другого;
- резкие торможения.

## Спрос

Отдельный файл, одна сеть проверяется при разной нагрузке (формат — замысел):

- источники машин на узлах `boundary` с интенсивностью по времени суток;
- матрица «откуда — куда»;
- пешеходы: точки появления на краях тротуаров, цели, интенсивность.

## Хранение данных

- **Эпизод** = хеш сети + спрос + зерно + действия контроллера. Детерминизм позволяет повторить эпизод точно.
- **Журнал событий** (Parquet или Arrow): ДТП с причиной, проезд на красный, опасные сближения, смены фаз, вызовы пешеходов.
- **Прореженные состояния** раз в 1–5 с: очереди, скорости и плотность по полосам — для анализа без повторного прогона.

## Отрисовка

Вид сверху, WebGL (PixiJS или deck.gl), без изометрии и без растрированных SVG.

- Сеть отрисовывается из скомпилированной сети при загрузке: асфальт из многоугольников, разметка по стилю границ полос, стрелки по `turns`, стоп-линии, зебры, светофоры по сигнальным группам.
- Кадры шлют только `{id, lane, s, v, state}` для машин и `{id, edge, s, offset}` для пешеходов, бинарно, около 10 Гц. Клиент переводит в координаты по той же геометрии и сглаживает движение между кадрами.
- Уровни детализации: издалека дорога — линия с цветом загрузки, вблизи — полосы, стрелки, машины.
- Слои отладки: цвет машины = скорость, точки конфликтов, линии опасных сближений с TTC, тепловая карта ДТП, очереди, наблюдение нейросети для выбранного перекрёстка, ошибки компилятора на карте.
- Повтор эпизода с перемоткой.
- Позже просмотрщик становится редактором: правка на карте → правка описания → перекомпиляция.

## Эксперименты и гипотезы

Эксперимент — основа мира, варианты-правки по стабильным id, спрос, контроллеры, зёрна, метрики (формат — замысел):

```json
{
  "experiment": "left_pocket_vs_shared",
  "world": "examples/cross.json",
  "variants": {
    "base": [],
    "shared": [
      {"op": "replace", "path": "/roads/rn/backward/1/turns", "value": ["straight", "left"]},
      {"op": "remove", "path": "/roads/rn/backward/2"}
    ]
  },
  "demand": "demand/evening_peak.json",
  "controllers": ["fixed_webster", "max_pressure", "nn:ckpt_042"],
  "seeds": 20,
  "metrics": ["delay", "throughput", "crashes", "ttc_lt_1_5", "pet_lt_1", "ped_wait"]
}
```

Правки — JSON Patch (RFC 6902) к описанию. Итог — таблица «вариант × контроллер × метрика» с разбросом по зёрнам.

## Нейросеть

- **Агенты**: один на перекрёсток (PettingZoo) или одна общая сеть (Gymnasium).
- **Действие** раз в шаг решения: оставить фазу или фаза k, длительности переходных стадий.
- **Наблюдение — граф**: узел — перекрёсток (фаза, стадия, сколько идёт), ребро — подход (очередь, сколько машин подъезжает в пределах 100 м, средняя скорость, ожидание первой, ждущие пешеходы). Подходит для графовой нейросети (PyTorch Geometric) и переносится на другие сети.
- **Награда**: минус ожидание машин и пешеходов (или «давление»), минус штрафы за опасные сближения и ДТП. Вес безопасности — параметр.
- **Эталоны**: фиксированный цикл по Вебстеру, адаптивный по детекторам, max-pressure.

## Язык и скорость

Python и numpy с массивами по полям. Если для обучения не хватит скорости, горячий цикл `step()` переносится на Rust (PyO3) без смены интерфейса.

## Порядок работы

1. Компилятор для прямых дорог и просмотр скомпилированной сети с разметкой.
2. Машины по коннекторам, светофоры с фиксированным циклом, живой просмотр.
3. Пешеходы, конфликты с `yield`, ДТП и опасные сближения, журнал.
4. Спрос, эксперименты с правками, эталонные контроллеры.
5. Среда для обучения и первая нейросеть: один перекрёсток, затем решётка 3 × 3.
